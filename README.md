## Installer chez soi

<img src="assets/loading.svg" width="70%" alt="Une barre de chargement qui avance et recule. Temps restant : trois minutes, puis deux ans.">

Rien à installer pour lire : [le site](https://agencekoeki.github.io/the-it-crowd/) est en ligne, et les fiches s'affichent telles quelles sur GitHub. Pour avoir le tout chez soi, il faut `git` et Python 3, sans aucune bibliothèque en plus.

1. Cloner le dépôt. La commande crée un dossier `the-it-crowd`.

   ```sh
   git clone https://github.com/agencekoeki/the-it-crowd.git
   cd the-it-crowd
   ```

2. Lire les fiches telles quelles : ce sont des fichiers Markdown, dans `kb/` et `kb/episodes/`. N'importe quel éditeur convient.

3. Ouvrir la vitrine. La page `docs/index.html` tient en un seul fichier, sans dépendance. Un double-clic suffit pour la voir ; pour qu'elle charge aussi le texte des fiches et des découpages dans son lecteur, servez le dépôt depuis sa racine :

   ```sh
   python3 -m http.server 8118
   # puis http://localhost:8118/docs/
   ```

4. Publier sa propre vitrine avec GitHub Pages : fourcher le dépôt, puis *Settings → Pages → Deploy from a branch*, branche principale, dossier `/docs`. La page déduit toute seule l'adresse du dépôt pour aller chercher les fiches. Les balises de partage, elles, pointent vers le site d'origine : l'adresse se change en tête de `tools/build_svg.py` (`REPO` et `SITE`).

5. Donner la base à une IA : lui faire lire `kb/README.md` d'abord, puis `kb/00-CONTRADICTIONS-ET-LACUNES.md`, puis les fiches utiles et les découpages des épisodes concernés. L'ordre compte, il est expliqué dans le README de la base.

Si quelque chose ne marche pas, la procédure est connue.

## Contribuer

Une correction vaut par sa source. Le projet tient à une discipline de preuve simple, et à rien d'autre.

| Étiquette | Ce qu'elle veut dire | Ce qu'elle ne veut pas dire |
|---|---|---|
| `[VÉRIFIÉ]` | Lu dans la source dont la clé suit l'étiquette | Ni « vu à l'image », ni « vrai dans l'absolu » |
| `[PROBABLE]` | Déduit de faits vérifiés, ou recoupé indirectement | Un fait établi |
| `[À VÉRIFIER]` | Sources contradictoires, source unique fragile, ou souvenir | Une affirmation réutilisable |
| `[ANALYSE]` | Interprétation ou jugement du rédacteur | Une information sur la série |
| `[VU À L'IMAGE]` | Constaté au visionnage, avec épisode et minutage | Vu en continu : c'est une image toutes les quelques secondes |
| `[SOUS-TITRES AUTO]` | Lu dans les sous-titres automatiques de YouTube | Entendu : le son n'a pas été écouté, et ces sous-titres se trompent |
| `[INTERPRÉTATION]` | Dans un découpage, ce que le rédacteur déduit d'une image | Un fait vu |

Les cinq premières servent dans les fiches, les deux dernières dans les découpages.

Les règles, dans l'ordre où elles servent :

- Chaque fait ajouté porte son étiquette et la clé de sa source. Pas de source, pas de `[VÉRIFIÉ]`.
- On ne transforme jamais un `[PROBABLE]` ou un `[À VÉRIFIER]` en affirmation. On le lève avec une source, ou on le laisse.
- La table des 25 épisodes de `kb/README.md` fait autorité. En cas d'écart, c'est la fiche qui a tort.
- Une contradiction entre deux fiches se consigne dans la fiche 00, avec les versions en présence. On ne l'efface pas.
- Une correction de relecture se marque `RC` et laisse le texte d'origine en place.
- Les répliques se citent en VO, une ligne au plus, avec la mention que le mot à mot n'a pas été contrôlé à l'écoute.
- Un découpage raconte l'action, il ne retranscrit pas les dialogues. Pour les dialogues, il y a un lien vers la vidéo officielle.
- Aucune capture, aucun extrait, aucun logo de la série dans le dépôt. Les détails sont dans [`LICENSE-NOTES.md`](LICENSE-NOTES.md).

Tout ce qui se compte ou se dessine est fabriqué par un seul script, sans dépendance : les <!--n:svg-->16<!--/n--> SVG de `assets/` (à partir de `tools/pixel.json`, police 5 × 7 et personnages), l'image de partage, l'index des fiches et des découpages que lit la page, la page d'erreur, et les chiffres de ce README. On modifie la source, on relance, on ne retouche rien à la main.

```sh
python3 tools/build_svg.py --sync-docs
```

À relancer après chaque modification de `kb/` ou de `tools/pixel.json`. Le relancer deux fois de suite ne change rien, ce qui est rare dans ce sous-sol.

L'arborescence réelle et la feuille de route sont dans [`STRUCTURE.md`](STRUCTURE.md). Les licences sont dans [`LICENSE`](LICENSE) : MIT pour le code, CC BY-SA 4.0 pour les textes, CC BY 4.0 pour le pixel art.
